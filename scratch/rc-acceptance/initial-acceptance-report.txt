# v0.8.0 release-candidate acceptance — The Living Continuity

Audit date: **2026-10-31 (Asia/Shanghai)**. Version: **0.8.0-beta.4**. Base commit: `6a9d4c2`; conclusions apply to the existing dirty working tree, including its untracked E3/Living States/Poetry implementation, not just that commit.

**Verdict: NO-GO for a final v0.8.0 release.** The original automated suites pass after removing sandbox filesystem restrictions, but targeted acceptance probes reproduce recovery-data loss and stanza identity/scope defects. Packaged Windows interaction acceptance is incomplete. Passing unit totals do not satisfy the requested release criterion.

This was an audit only. No production behavior, versions, existing implementation files, real notebooks, commits, tags, pushes, or releases were changed. New files are this report and disposable audit fixtures/logs. The Rust fixture intentionally includes a failing release-invariant assertion; it was temporarily run as a Cargo integration test, then moved into `scratch/rc-acceptance/rust-boundaries.rs` so it does not alter normal test discovery. Earlier provisional fixture compile/parent-directory mistakes were corrected and are not product findings.

## 3. Cross-feature acceptance

### Echo E3 × Living Entity States

Executed E3 tests bind exact UTF-16 pronoun spans to canonical target IDs, preserve identical-word independence, shift/detach/re-anchor spans, cover CRLF/astral Unicode, and exercise CodeMirror undo/redo. Living States tests 16–20 project the same target across different chapter milestones and nested relationship targets, resolving historical properties and relationships without changing the target identity. The nested test calls catalog projection with the chapter milestone; it does not click through a native dossier.

E3 test 17 registers and drains a real child flush handler with SaveCoordinator and edits arriving during an in-flight save. App source uses `flushChildEditors`, workspace flush, navigation generations, and failure checks before document/studio changes (`src/App.tsx:232`, `:608`, `:687`). This is useful integration evidence, but the combined journey “bind → edit → immediately switch studio → quit/restart → inspect another milestone → undo/redo” has **not** been executed in a packaged app. It remains an acceptance gap.

Real Rust Portable tests independently verify E3 anchors/timestamps/remapped targets and historical relationship/property-change IDs. The TypeScript Living States tests called “Serialization & roundtrip portability” and “Separate Copy” are respectively JSON serialization and simulated remapping; those names alone do not prove `.mcuniverse` behavior.

### Poetry × Emotional Cipher

The disposable [TypeScript probes](../scratch/rc-acceptance/boundaries.test.ts) create three stanzas with `love → ember / silence / home`. Actual `.mcpoem` filesystem export/reparse preserves complete metadata, and actual `.mccipher` file reparse/decode recovers the three original stanzas. Conflict cancellation leaves the input metadata unchanged; conflict resolution and switching back within an intact in-memory metadata object preserve mappings. Explicit move/insert/delete/split utility checks pass.

**11 probes: 6 pass, 5 fail, exit 1.** [Results](../scratch/rc-acceptance/boundaries.log). Failures are listed in section 10. In particular, the same scope transition fails after saving/reopening a Whole Poem record with only `per_stanza_backup`, matching the save shape in `EmotionalCipherModal.tsx:1481`.

Source inspection confirms Poetry UI add/delete/up/down operations update stanza entries together with text; delete archives active removed rules. The current Poetry Studio does not expose explicit split/merge handlers or a shared metadata undo stack. Those utilities existing and passing isolated checks do not establish editor split/merge or undo acceptance. Inserting a blank line can structurally change serialized text without coordinating a metadata split; reopen/reconciliation needs native verification. Textarea undo alone cannot certify structural/mapping undo. Recovery reassignment and conflict-dialog cancellation were inspected in source; their actual clicks, save/close/reopen, and undo remain pending.

## 4. Poetry package compatibility

| Boundary | Verified result | Qualification |
| --- | --- | --- |
| `.mcpoem` | TS serializer → disk → parser preserves full v2 cipher metadata, including both backups and unresolved entries | Envelope remains version 1; cipher metadata is version 2. Rust has no dedicated mcpoem parser; canonical metadata storage/Vault is tested separately |
| `.mccipher` | Three independent stanza mappings survive JSON/file validation and decode | Envelope is version 1 with algorithm 2.0; validator rewrites outer algorithm to 1.0. Recovery fields are absent from the key/package schema |
| `.mckey` v1 | Real Rust file import accepts a legacy key and defaults algorithm to 1.0 | Existing Rust dictionary tests also cover save/export/reimport |
| `.mckey` v2 | TS-produced file → Rust import/save/export preserves active stanza entries, scope, algorithm 2.0 | Supplied recovery fields are silently discarded by Rust serde; TS key validation does the same |

The [Rust disposable fixture](../scratch/rc-acceptance/rust-boundaries.rs) uses only `tempfile` notebooks and public production APIs. Its final five probes pass four cases and fail the recovery-field invariant. Vault restores full poem metadata; Portable archive scope excludes Poetry; v1 and TS→Rust v2 active-key probes pass. There is no Rust `.mccipher` decoder to test: that format is handled in TypeScript, while Rust stores its key/canonical document data. It would be misleading to claim a Rust mccipher round trip.

No-loss acceptance is therefore **not met**. `.mcpoem` and Vault carry the complete metadata object, while the current key-only `.mckey`/`.mccipher` boundary cannot preserve the author's scope backups or unresolved mappings. Treating those as optional editing state does not satisfy the mission's explicit preservation requirement; either preserve them or explicitly reject/disclose unsupported metadata before export/import.

## 5. Portable Universe compatibility

These are real backend tests, not frontend JSON simulations. [Original Rust log](../scratch/rc-rust-unrestricted.log).

**Poetry stanza metadata is outside the supported archive scope.** `portable/collect.rs` inventories Lorebooks, Backups, and Attachments, and the validator requires Lorebook documents. The new real-export probe creates a Poetry document carrying the same `universe_id` and complete cipher metadata; neither the document nor a Poetry payload is included in the archive. This is a scope limitation, not proof that an imported supported Lorebook lost a field. The requested combined Universe+Poetry portability criterion remains unmet. Unknown opaque metadata does not automatically establish safe Separate Copy remapping.

## 11. Recommended remediation

1. Restore/reconcile saved per-stanza backups when returning from Whole Poem; retain IDs, manifests, unresolved entries and conflicting independent mappings across save/restart. Add the failing scope-reopen probe to permanent coverage after fixing production behavior.
2. Define the supported recovery metadata contract for `.mckey`/`.mccipher` across TS and Rust. Preserve it or reject/disclose it explicitly at the boundary. Test TS→Rust→TS actual files, including both backups and unresolved entries, not only active mappings.
3. Reconcile content fingerprints before the same-count positional fallback; preserve uncertainty as unresolved. Make merge conflicts explicit and recoverable before exposing/claiming split/merge support. Recheck structural editing and metadata undo behavior in the actual UI.
4. Preserve mccipher algorithm 2.0. Confirm envelope versions and algorithm versions independently in tests.
5. Resolve `.mcuniverse` Poetry scope without treating this audit as authorization to add a feature. Either revise the acceptance claim to the supported scope or schedule separately authorized work; Vault already provides full-notebook portability.
6. Complete the isolated Windows installer and interaction checklist, record hashes/screenshots/results, then rerun all suites and boundary probes. Refresh documentation and the stale documentation checker. Treat strict Clippy policy separately from correctness blockers.
